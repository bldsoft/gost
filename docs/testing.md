# Testing

A gost service is tested at three levels, all present in [`examples/notes`](../examples/notes):

| Level | Needs | Command | Example |
|---|---|---|---|
| Unit (service, config) | nothing | `go test ./...` | [`note_service_test.go`](../examples/notes/pkg/service/note_service_test.go) |
| Route and controller | nothing | `go test ./...` | [`microservice_test.go`](../examples/notes/pkg/microservice/microservice_test.go), [`note_controller_test.go`](../examples/notes/pkg/controller/rest/note_controller_test.go) |
| Integration (repositories) | Docker | `go test -tags=integration_test ./...` | [`note_repository_integration_test.go`](../examples/notes/pkg/repository/note_repository_integration_test.go) |

Use `testify/require`, table-driven cases, `t.Parallel()` where state allows, and `-race`.

## Unit tests with mocks

Service tests mock the repository interface the service itself declares. Mocks are generated by
mockery (v3, testify template, expecter API) into a `mocks` package next to the interface:

<!-- source: examples/notes/pkg/service/interface.go -->
```go
//go:generate go tool mockery

type NoteRepository interface { ... }
```

<!-- source: examples/notes/pkg/service/note_service_test.go -->
```go
repo := mocks.NewNoteRepository(t)                    // asserts expectations in t.Cleanup
note := &entity.Note{Title: "  hello  "}
repo.EXPECT().Insert(mock.Anything, note).Return(nil)

require.NoError(t, service.NewNoteService(repo).Create(context.Background(), note))
require.Equal(t, "hello", note.Title)
```

Variadic parameters such as `opts ...*repository.QueryOptions` are recorded as **one slice
argument**, so expectations use a slice or a `mock.MatchedBy(func(opts []*repository.QueryOptions) bool)`:

```go
repo.EXPECT().FindByID(mock.Anything, id.Hex(), []*repository.QueryOptions{{Archived: true}}).Return(want, nil)
```

Hand-written fakes are fine for tiny interfaces or when you want to assert inside the fake; the
controller test uses a struct of function fields. Do not mix styles in one package.

Mocks are generated code: never edit them, keep them committed, and let CI prove they are
current (`go tool mockery && git diff --exit-code`).

## Route tests

Never call `server.Start()` in a test: it registers on the global `http.DefaultServeMux`. Build
a chi router and mount the microservice exactly as the server would:

<!-- source: examples/notes/pkg/microservice/microservice_test.go -->
```go
var cfg config.Config
require.NoError(t, gost.SetDefaults(&cfg))
cfg.AdminAPIKey = testAPIKey
require.NoError(t, gost.Validate(&cfg))

r := chi.NewRouter()
r.Group(microservice.New(cfg).BuildRoutes)

req := httptest.NewRequest(http.MethodGet, "/notes/env", nil)
req.Header.Set(microservice.APIKeyHeader, testAPIKey)
rec := httptest.NewRecorder()
r.ServeHTTP(rec, req)
require.Contains(t, rec.Body.String(), `AdminAPIKey: '****'`)
```

This works because `New` does not touch the network; database connections live in
`Initialize()`, which the test does not call. The same test proves that `/ping`, `/version` and
`/env` exist and that secrets are masked.

To test with the real middleware chain (request ID, recoverer), add
`middleware.RequestID`, `middleware.Recoverer` to the router, mount
with `r.Group(ms.BuildRoutes)` and serve through `httptest.NewServer`; an e2e harness built this
way can also run `goleak` in `TestMain`.

## Integration tests

Put them behind the `integration_test` build tag, the same tag gost uses, so `go test ./...`
stays fast and `make test-integration` runs everything. `mongo/mongotest.Start` launches a
single-node replica set and returns a `mongo.Config` pointed at it. Docker must be running;
nothing is shared with a database you started yourself.

<!-- source: examples/notes/pkg/repository/note_repository_integration_test.go -->
```go
//go:build integration_test

func TestMain(m *testing.M) {
	cfg, cleanup, err := mongotest.Start(context.Background())
	if err != nil {
		_, _ = fmt.Fprintf(os.Stderr, "%v\n", err)
		os.Exit(1)
	}

	db = mongo.NewStorage(cfg)
	db.Connect()

	code := m.Run()

	ctx := context.Background()
	_ = db.Db.Collection(repository.CollectionName).Drop(ctx)
	_ = db.Disconnect(ctx)
	cleanup()
	os.Exit(code)
}
```

Run locally:

```bash
go test -race -count=1 -tags=integration_test ./...
```

What to cover in repository tests: the soft-delete contract (`Delete` hides, `Archived: true`
shows, hard delete removes), `ErrNotFound` on unknown IDs, and any index-dependent query.

## Config tests

Assert your defaults and `Validate` rules with `gost.SetDefaults` and `gost.Validate` (not
`ReadConfig`, which is fatal), and keep the `config.md` golden test from the example so the env
table cannot drift. See [Configuration](configuration.md#generating-configmd).

## Tooling

- `make test` runs unit and route tests; `make test-integration` adds the tag.
- `gotestsum --format=testname -- -race -tags=integration_test ./...` is what gost's own CI
  runs; the service CI template does the same.
- Go 1.25+ `testing/synctest` is handy for ticker-driven code; the purger test instead uses a
  short interval and a channel.
