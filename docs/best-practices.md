# Best practices and anti-patterns

Collected from several production services built on gost. Each "don't" was observed in real
code; the "do" is what the example service implements.

## Configuration and secrets

| Do | Don't |
|---|---|
| Type secrets as `config.HiddenString`; `/env` and the startup dump then show `****` | Keep API keys or passwords as plain `string` (they are printed by `FormatEnv` at every start) |
| Leave secrets without a default and reject empty values in `Validate` | Hard-code a default API key or discovery secret in `SetDefaults` |
| Set `c.Server.ServiceName`, `ServiceBindAddress`, `Mongo.DbName` in your `SetDefaults` | Call `c.Server.SetDefaults()` / `c.Mongo.Validate()` yourself; gost already walks the tree |
| Use `SERVICE_BIND_ADDRESS` and `SERVICE_INSTANCE_NAME` | Use the deprecated `SERVICE_HOST`/`SERVICE_PORT`/`SERVICE_NAME` |
| Commit one `config.md`, regenerated by the golden test | Keep two copies (root and `cmd/<svc>/`) that drift apart, or hand-edit the table |
| Use one env prefix style (none, or a short prefix such as `SP_`) consistently | Mix `Service`/`Server`, `Database`/`Mongo` names across services |
| Name the env variable in every `Validate` error | Return bare `errors.New("invalid")` |

## Wiring and lifecycle

| Do | Don't |
|---|---|
| Register migrations before `Connect`; connect in `Initialize()` with `DBConnectAsync` | Call `db.Connect()` directly (it panics) or connect inside `New` |
| Make everything long-lived an `AsyncRunner`; order shutdown with `AsyncJobChain` | Spawn goroutines with no stop, or write your own signal handling |
| Declare interfaces in the consuming package; assert conformance with `var _ I = (*T)(nil)` | Import the implementation package from the service layer |
| Keep `New(cfg)` network-free so tests can build routes | Open sockets or connect in constructors |
| Protect `/env`, `/stat`, feature flags, changelog with an API key or admin auth | Expose configuration dumps publicly |
| Pass the **instance name** to `feature.NewMongoRepository` and keep the repository | Pass the DB name, or create the repository and discard it (flags never update) |
| Register feature definitions with `AddFeatureMigration` | Declare features in code only; they stay invisible in the UI |

## Code and tests

| Do | Don't |
|---|---|
| Map errors with `errors.Is` in one `responseError` per controller | Compare `err == ErrX`, or leak internal error text on 5xx |
| Mock the narrow interface you declared (mockery) or write a small fake | Mock `mongo.Repository` with all 30 methods |
| Put integration tests behind `integration_test`; skip locally, fail in CI | Let integration tests silently skip in CI, or panic when the DB is missing |
| Build a chi router and call `BuildRoutes` in tests | Call `server.Start()` in tests (global mux) |
| Pin one gost version per service and bump deliberately | Carry five different gost pseudo-versions across a monorepo |
| Ship `.golangci.yml` from the template and lint before every push | Have no lint config, or sprinkle `//nolint` |
| Keep comments for contracts and invariants with a failure mode | Comment what the code already says |

## Repository hygiene

- One `VERSION` file; CI checks tags against it.
- `.dockerignore` excludes `.env*`; `.gitignore` excludes `bin/` and `*.out`.
- Delete stale artefacts (`routes.md`, `restapi.yaml`, old compose files) instead of letting them
  contradict the code. A doc that is wrong is worse than none.
- Go version must agree between `go.mod`, the Dockerfile and CI.
- Avoid cross-module `replace` directives between services; extract shared code into a library.

## Known gost quirks to design around

| Quirk | Consequence |
|---|---|
| `server.Start()` registers on `http.DefaultServeMux` | One server per process; never `Start()` in tests |
| `Shutdown` receives a cancelled context | In-flight requests are not drained; keep handlers short or front with a draining proxy |
| `mongo.Storage.Connect()` panics | Always go through `storage.DBConnectAsync` |
| `Delete` soft-deletes unless `QueryOptions{Archived:false}` | Decide explicitly which you want; reads hide archived rows by default |
| `inhouse.Config` ships a default `SECRET_KEY` | Override `DISCOVERY_INHOUSE_SECRET_KEY` in every environment |
| `cache/v2/aerospike.Config` is not an `IConfig` | Apply its defaults yourself |
| `mongo/mock` is stale gomock | Use `mongo/mocks` or your own interface mocks |
| `GetAsyncRunners` is collected after `BuildRoutes` | Pre-traffic work goes in `Initialize()` |
